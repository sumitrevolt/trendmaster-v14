# TrendMaster v14 — Risk Model

This document explains every gate a trade must pass before capital is at risk, the default parameters, where to change them, and the production incidents that motivated each one. It is the single source of truth for "why didn't that trade fire?" questions — keep it accurate when the gates change.

## Architecture summary

TrendMaster is a two-process system. The Python brain (`ai_trading_agents/trend_master_brain.py`) reads MT5 bars, runs feature engineering and a LightGBM classifier (with a rule-based fallback), passes the candidate signal through a stack of profit filters, and writes a JSON file the EA reads. The MQL5 EA (`AI_SUPERBB_v14_TrendMaster.mq5`) independently computes its own three-of-three confirmations and only fires an order when both sides agree. Either process can run without the other, but risk is enforced on both sides so a crash in one never bypasses the protections in the other.

## Entry gates

For an order to fire the brain and the EA must both approve. On the brain side a candidate signal has to clear, in order, the ML inference gate (minimum confidence of `MIN_ML_CONFIDENCE`, default 0.58), the multi-timeframe alignment check (each enabled TF from `mtf_alignment` must show an EMA stack consistent with the proposed direction), the profit-filter stack described below, and the multi-agent vote (trend, momentum and timing agents must all agree). If any gate fails the brain writes `NONE` to the signal file and the EA will not enter on that bar.

On the EA side the three confirmations are independent of the brain. C1 requires EMA(20) > EMA(50) > EMA(200) stacked in the direction of trade, SuperTrend(10, 3.0) pointing the same way, ADX(14) at or above 22, and price beyond the slow EMA. C2 requires price on the right side of the Bollinger(20, 2) middle band with current band width at least 0.9× the median of the last 50 widths — this rejects low-volatility squeezes where C1 often gives a false positive. C3 requires MACD(12, 26, 9) momentum to be rising and positive for longs (symmetric for shorts), measured either by histogram-over-previous or by the MACD line being above both its signal and zero. The same logic is mirrored in `ai_trading_agents/ea_confirmations.py` so backtests can reproduce the EA's accept/reject decision bar-for-bar. Parameters live in the EA's input declarations at the top of the .mq5 file; keep those in sync with the `EAParams` dataclass if you change either side.

## Profit-filter stack

The profit filters in `ai_trading_agents/profit_filters.py` are layered after the ML and MTF checks but before the agent vote. They are authoritative — if any one vetoes, `direction` is forced to `NONE` and the trade does not fire. Each gate can be toggled individually in `config/settings.PROFIT_OPTIMIZER`.

Spread guard rejects trades when the current broker spread exceeds a configurable multiple of the 14-period ATR. Volatility regime rejects both unusually quiet markets (ATR below the Nth percentile of recent history) and unusually violent ones (ATR above a higher percentile), so the brain only trades its comfort zone. Daily profit lock halts new trades once the session is up `daily_profit_lock_pct` from the recorded start-of-day equity — the "don't give it back" gate. Loss-streak cooldown watches the most recent results in persistent state; after N consecutive losses (default 3) it sets `cooldown_until_ts` to block new entries for `cooldown_minutes`, letting the brain cool off after a drawdown run. Session window limits trading to a configurable list of UTC hour ranges — the default only trades during the London and New York sessions where most pairs actually move. News blackout reads `config/news_calendar.json` and refuses to trade within `news_window_minutes` (default 30) either side of any event whose impact is in `news_impact_levels` (default `high`) — this is why a FOMC release at 18:00 UTC will freeze signals from 17:30 to 18:30 UTC.

Persistent state for loss streaks, cooldown timers, daily equity snapshots and the recent-results rolling window lives in `ai_trading_agents/brain_state.json`, written atomically by `ai_trading_agents/state_store.py`. The brain loads this once on startup and checkpoints it every N ticks (default 10) plus on every shutdown, so a restart never forgets an in-progress cooldown or doubles up on the daily profit lock.

## Position sizing and exits

Position size is set by the EA's `InpLotFixed` or `InpRiskPct` input — when risk-percent mode is on, the EA computes lots from account equity, the stop distance in pips, and the pip value for the symbol. The stop distance is ATR-derived (`InpSL_ATR_Mult`, default 1.5× the current 14-period ATR) and the take-profit uses the same ATR anchor scaled by `InpTP_ATR_Mult` (default 2.5×, i.e. a 1.67 reward-to-risk target). The EA manages exits live, not the brain: once an order is open the EA's `ManageOpenPositions()` handler trails the stop with an adaptive scheme tied to ATR and price movement. The brain's only job post-entry is to stop writing BUY signals when conditions flip — the EA does not flatten on `NONE`, it only refuses *new* entries, so an open trade runs on its own trailing logic until the stop or take-profit hits.

## Multi-symbol risk

When `MULTI_SYMBOL` is True the brain iterates every symbol in `TRADING_PAIRS` on each tick (default 21 symbols across metals, forex, crypto and commodities). Each symbol writes its own signal file (`trendmaster_signals_{SYMBOL}.json`) and the EA must be configured to read the matching file. Crucially, the profit-filter stack runs per-symbol — the daily profit lock applies to overall account equity, but the cooldown and loss-streak are also account-wide because they use the shared `recent_results` list. This is intentional: three losses on GBPJPY plus two on USDJPY still count as a five-loss streak, not separate per-symbol streaks, so a correlated drawdown across JPY pairs triggers the cooldown exactly as if it were one pair losing five times.

## Operational safeguards

The brain refuses to start a second instance. `ai_trading_agents/process_lock.py` writes a PID to `logs/brain.lock` with an OS-level file lock (msvcrt on Windows, fcntl on POSIX) and checks PID liveness on startup — a stale lock from a crashed process is cleaned up automatically, but a live second brain is refused. Two brains writing the same signal file would cause torn JSON reads and duplicate orders, so this guard is non-negotiable.

Logs rotate at 50 MB × 5 backups via a `RotatingFileHandler` in `_setup_logging`, capping `logs/trend_master_brain.log` at 250 MB regardless of runtime. MT5 connection failures retry with exponential backoff in `_mt5_initialize_with_retry`, and individual bar-pull calls retry once with a quick re-init in `_mt5_copy_rates_safe` — a broker push delay no longer kills the brain.

Telegram provides the out-of-band channel. On boot the brain posts a heartbeat. On every direction change per symbol it posts a signal alert (throttled by `min_interval_s` to stop 250 ms loops from blasting the phone). A command listener in `ai_trading_agents/telegram_commands.py` responds to `/status`, `/pnl`, `/symbols`, `/ping` and `/help` — only from the configured `TELEGRAM_CHAT_ID`, so the bot's username being public is not a problem. The supervisor in `tools/supervisor.py` watches both brain and dashboard, restarts them with exponential backoff, and pushes a Telegram alert on every brain crash and restart. A daily PnL summary fires once per UTC day after `daily_summary_hour_utc` (default 22:00), idempotent via `daily_summary_sent_date` in persistent state so a restart in the send window can't double-post.

## Failure modes that are explicitly tolerated

The Telegram notifier, command listener and all alert paths swallow every exception. A revoked bot token, a DNS blip or a Telegram outage must never kill the trading loop — worst case the user stops getting phone alerts and sees log warnings. Similarly, news calendar loading failures downgrade to "no blackout" rather than "block everything" — the filter fails open because a stale calendar file is a more likely cause than an actual event. The profit-filter evaluation itself is wrapped in try/except in `tick_once`: if any filter crashes due to a bad input shape or a library mismatch the brain logs a warning and continues with the pre-filter direction, rather than blocking all trades because one metric misbehaved.

## Where parameters live

Everything the operator can tune lives in `config/settings.py` (trading pairs, profit optimizer flags, news window, daily summary hour, per-symbol timeframe overrides) or in the EA's input block at the top of `AI_SUPERBB_v14_TrendMaster.mq5` (indicator periods, SL/TP ATR multipliers, confirmation toggles). Secrets — broker credentials and the Telegram bot token — live only in `.env` files under `config/` and `ai_trading_agents/` and are guarded against accidental commit by a CI check and a pre-commit hook; `.env.example` files in both directories document the required keys without holding real values. If something feels like it should be configurable and isn't, the answer is almost always to add it to `config/settings.py` rather than hard-code it in a new place.
